# Guitar Auto Tab 🎸

YouTube・音声/動画ファイルから**ギタータブ譜を自動生成**するローカルWebアプリ。
個人利用・完全無料（有料API・課金トークン一切なし）。採譜エンジンは無料OSS（librosa等）で動作します。

## 機能

- **映像を主・音声を従の採譜**: まず映像の演奏動作（ピッキング/ストラム）を解析し、**映像で演奏が確認できるノートだけ**をタブに出力。演奏していない位置に出る「関係ない音」（バックの原曲・ボーカルの残り等）は映像の根拠で除去します。映像のブリッジ側のピッキング位置は**どの弦を弾いているか**の手がかりとして弦割当にも反映
- **指板のポジションマーク（黒丸）からフレット位置を推定**: 黒丸があるフレット（3/5/7/9/12/15/17/19/21、12のみ黒丸2つ）の並びがギターの物理配置に合うかを検証して指板の座標を校正し、演奏中の**左手の位置から何フレットを弾いているか**を推定してタブのフレット割当に反映
- **ギター音色モデル（6弦1F〜1弦22Fの学習）で無関係な音を除去**: テレキャス・レギュラーチューニングの全ポジション（6弦1フレット〜1弦22フレット＋開放弦）の「ギターの音」を音色辞書として学習。検出ノートの**倍音の並び・アタック（弾いた瞬間が最大）・減衰**がギターの音に合うかを照合し、ボーカル・パッド（持続音）・ノイズなどタブに載せると無関係な音になるものはここで除去します（各ノートに一致度 `tone` を記録、除去数は `meta.tone_dropped`）
- **メロディモード（単音弾き・リードパート）**: 単音フレーズを採譜し、6弦×フレットのタブ譜へ自動変換（手ポジション移動を最小化する動的計画法）
- **複数本指・同時発音に対応**: ダブルストップ・オクターブ・小コードなど複数弦を同時に弾く部分を最大3声まで検出。開始時刻が揃ったノートは**弦が重ならない組み合わせ**としてタブにまとめて配置されます。同時に鳴らせるのは**1手で押さえられる範囲のみ＝開放弦を除くフレット開き3以内**（例: 8フレットを鳴らすとき同時に鳴らせるのは5〜11フレットの間で、最大値−最小値が3まで。開放弦は指を使わないので開きに数えません）。この範囲に収まらない同時発音は物理的に押さえられない（=誤検出の疑い）ため、**根拠の弱い声から除きます**
- **コードモード（バッキングパート）**: コード進行を検出し、**コード / パワーコード**の出力形式を選択可能
- **ミュートの音声確認**: 全弦を押さえているように見えても実際に鳴っていない弦（ミュート）は、倍音の残差判定で**タブ譜から自動的に除きます**（映像だけでなく音声側の根拠を必ず確認）
- **映像フレームリンク（ブリッジ側の確認用）**: ノート位置の映像フレームを自動抽出し、再生中に表示。どの弦を弾いているかをブリッジ側の映像で照合できます
- **音源分離（Demucs・無料OSS）**: ミックスからギター成分だけを自動抽出して採譜。バックの原曲（ボーカル・ベース・ドラム）による誤検出を大幅に抑制（使用時はタイトルに「音源分離: ON」と表示）
- **動画と同期して確認**: YouTube動画や動画ファイルを再生しながら、タブ譜に現在位置カーソルが追従（現在の弦行もハイライト）
- **保存**: タブ譜を **PDF / TXT（ASCIIタブ）/ analysis.json** として保存
- **Claude Code連携（採譜の磨き上げ）**: analysis.json を書き出し → Claude Code に渡して採譜を修正 → 取り込みで反映

## 必要なもの

- Windows（macOS/Linuxも可、要調整）
- Python 3.12（採譜ワーカー用。`winget install Python.Python.3.12` で導入可）
- Node.js LTS（Webアプリ本体の実行・ビルド用）
- ffmpeg は不要（pip の `imageio-ffmpeg` 同梱バイナリを使用）

## セットアップ

```powershell
cd Guitar-auto-tab
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
cd web
npm install
```

### （推奨）音源分離 Demucs の導入 — 採譜精度が大きく向上します

```powershell
.\.venv\Scripts\python.exe -m pip install torch==2.5.1 torchaudio==2.5.1 --index-url https://download.pytorch.org/whl/cpu
.\.venv\Scripts\python.exe -m pip install demucs
```

初回の解析時に学習済みモデル（約330MB）が自動ダウンロードされます（すべて無料・外部API不使用）。
未導入でも動作します（その場合は元音声のまま解析し、精度は下がります）。

## 起動

```powershell
run.bat
```

または（手動）:

```powershell
cd web
npm run build
$env:GAT_ROOT = (Resolve-Path ..).Path        # output/ と .venv の基準（リポジトリルート）
$env:GAT_PYTHON = "..\.venv\Scripts\python.exe"
node .output\server\index.mjs                  # http://127.0.0.1:8000
```

`run.bat` 経由の場合、起動完了後にブラウザが自動で開きます。手動起動時は <http://127.0.0.1:8000> を開いてください（ポートは `PORT` 環境変数で変更可）。

開発時はビルド不要の開発サーバーも使えます:

```powershell
cd web
$env:GAT_ROOT = (Resolve-Path ..).Path
$env:GAT_PYTHON = "..\.venv\Scripts\python.exe"
npm run dev     # http://localhost:3000
```

## 使い方

1. **出力したいパート**を選択（メロディ / コード）。コードのときは**コード / パワーコード**も選択
2. **YouTube URL** を貼るか、**音声/動画ファイル**を選択
3. **解析開始**（30秒〜数分。曲の長さ次第）
4. 再生しながらタブ譜を確認（カーソルが追従）
5. **PDF保存 / TXT保存** で書き出し

### Claude Code で採譜を磨く（個人利用フロー）

完全自動の結果に誤りがある場合の手順:

1. **analysis.json書き出し** でデータを保存
2. Claude Code にファイルを渡して修正を依頼（例: 「`output/xxxx/analysis.json` の採譜を確認して、不自然なノート分割とポジション選択を直して」）
3. 修正後のJSONを **磨き上げJSONを取り込み** で読み込み → 表示・PDF/TXT保存に反映

元の解析で映像フレームが抽出されている場合（`output/xxxx/frames/`）、取り込み後も各ノートの `"frame"` から同じフレーム画像を参照できます。どの弦を弾いているかの確認にはこのフレーム（ブリッジ側の見え方）を、ミュートの有無は音声の根拠を併せて確認してください。

## 動作テスト

```powershell
.\.venv\Scripts\python.exe tests\test_dsp.py   # DSP知覚層（採譜・音色・映像・ワーカーCLI）
cd web
npm test                                        # 決定ロジック・契約・パイプライン（vitest）
```

- **Python側（`tests/test_dsp.py`）**: 既知のメロディ/同時発音（ダブルストップ・オクターブ）/ミュート付きコード/映像動作/指板マーカー（黒丸）を合成して、メロディ採譜、ギター音色学習（6弦1F〜1弦22F）による無関係な音の判定、フレーム抽出、ワーカーCLIのJSON契約までを検証
- **TypeScript側（`web/tests/`）**: 弦/フレット割当（同時発音の押さえ方の物理制約＝開放弦以外のフレット開き3以内・押さえられない同時発音は弱い声から除く）、ボイシング、映像ゲート（関係ない音の除去・弦位置とフレット位置の反映）、ASCIIタブ、zod契約、ワーカーをスタブしたパイプライン（tone除去→割当→フレームリンク→PDF/TXT/JSON保存、磨き上げJSON取り込み）を検証

  sep.py             # 音源分離（Demucs: ミックスからギター成分を抽出）
  melody.py          # メロディ採譜（pyin + 多声音検出: ダブルストップ等・音での確認付き）

  shared/
    schema.ts        # 契約（zod）— API/ワーカー/analysis.json の単一情報源
    events.ts        # ノートイベント共通処理（同時発音のグルーピング等）
  server/
    api/             # Nitro APIルート（/api/analyze /api/import /api/jobs/...）
    core/
      pipeline.ts    # 解析パイプライン統括（tone閾値・映像ゲート・割当・保存）
      tabassign.ts   # ノート→弦/フレット割当（DP・開放弦除く開き3以内の制約）
      voicing.ts     # コード→押さえ方（開放/バレエ/パワーコード・同じく開き3以内）
      gate.ts        # 映像（演奏動作）に忠実なノート/コードの選別
      grid.ts        # タブ譜のグリッド配置計算
      render.ts      # ASCIIタブ出力
      pdf.ts         # PDF出力（pdfkit・日本語フォント対応）
    worker/client.ts # Pythonワーカーの実行（subprocess + JSON契約検証）
  pages/ components/ composables/ utils/ assets/   # UI（Vue SFC）
  tests/             # vitest（決定ロジック・契約・パイプライン）

## 言語の使い分け

「無理に1言語へまとめない」方針で、コンポーネントごとに**妥当性とデータのやり取りの滑らかさ**で言語を選ぶ:

- **DSP知覚層（採譜・音源分離・映像解析）= Python（`worker/`）** — librosa / numpy / Demucs の生態系が唯一揃う場所。ここをTypeScript等で書き直すと精度も無料維持も崩れるため、Pythonが妥当
- **決定ロジック・譜面描画・API・UI = TypeScript / Nuxt 3（`web/`）** — 弦/フレット割当（DP）、ボイシング、映像ゲート、タブ描画、PDF出力、画面を1言語へ集約。UI近傍のロジックの変更が1箇所で完結する
- **Python↔TypeScript 境界 = JSON 契約** — `worker/` は CLI として呼ばれ、知覚結果の JSON を返す。型は `web/shared/schema.ts`（zod）が単一情報源で、ワーカー出力もAPI応答もここで検証する（手書き二重管理・コード生成の連鎖なし）
  - API（analysis.json）の形式を変えたら: `web/shared/schema.ts` を書き換えて `npm run test`（`schema.spec` / `pipeline.spec` が契約を検証）
  - ワーカーのJSON形式を変えたら: `web/shared/schema.ts` の `PerceptionResult` と `worker/__main__.py` を揃えて `tests\test_dsp.py` の `test_worker_cli` を実行

## 制限・既知の課題

- 映像を主に採譜するため、**映像に演奏が映っていない動画**（顔出しのみ・歌詞動画等）では演奏動作とノートが対応せず、ノートが減ることがあります。その場合は音声ファイルとして解析するか、磨き上げフローで補ってください（映像に動作が検出されない場合は安全側に倒して音声の結果をそのまま使います）
- フレット位置の推定は**指板のポジションマーク（黒丸）が映像に見えている場合のみ**有効です。暗い映像・指板が映っていない動画では従来どおり音声からの割当になります（マーカーが無いのに誤検出した場合は物理配置の検証ではじくため、割当が壊れることはありません）
- 音色による無関係な音の除去は**ボーカル・パッド・ノイズなど「ギターでない音」が対象**です。バックの原曲に元から入っているギターの音は音色的にはギターそのものなので除去できず、その場合は映像動作による選別と音源分離（Demucs）の効果に依存します
- チューニングは**標準（EADGBE）**固定（キャポ・変則対応は今後）
- フルミックスの曲でも音源分離（Demucs）でギター成分を抽出してから採譜するため誤検出は大幅に減っていますが、バックの原曲に同じフレーズのギターが大きく入っている場合は影響を受けることがあります。分離のため解析に数十秒（曲長・CPUに依存）が加算されます
- YouTubeの音声取得は個人利用を前提とした機能です（公開サービス化する場合は規約・権利の確認が必要）
- 拍子は4/4前提で小節線を描画（テンポ検出に依存）
